## DB-20260719-01 Claude Code v2.1.214:権限チェックの迂回・誤承認を修正するリリース

**要点: 「許可ルール=統制」の前提を崩すバイパスが実在した。組織展開では権限設定を多層防御の一層と位置づけ、セキュリティ修正への即応を標準に組み込むべき。**

### 確認された事実

Anthropic が Claude Code v2.1.214 を GitHub Releases で公開した(2026-07-18)。リリースノートの要約で確認できた修正は以下の通り。

- `Edit(src/**)` のような単一セグメントの `dir/**` 許可ルールが、本来の `<cwd>/dir` 配下だけでなく、ツリー内の任意の場所にある `dir/` ディレクトリへの書き込みを自動承認していた問題を修正。
- Windows PowerShell 5.1 セッションで実行されるコマンドに影響する、権限チェックのバイパスを修正。
- bash と権限アナライザで解釈が異なるファイルディスクリプタのリダイレクト形式について、Bash の権限チェックがフェイルクローズ(安全側で拒否)するよう修正。
- 10,000文字を超える長いコマンドを権限チェックが誤判定していた問題を修正。

補足: 取得した要約は末尾が途切れており、10,000文字超コマンドの修正後の挙動の全文はこの要約からは確認できていない。

### なぜ重要か

**エージェントCLIの権限制御そのものに、自動承認の過剰マッチとチェックバイパスが存在したことが一次情報で確認された。**

- 許可ルール(allow rules)を統制の唯一の根拠にしている組織は、旧バージョンでは意図より広い操作が自動承認されていた可能性がある。
- PowerShell 5.1 は企業のWindows端末で標準的に残っている環境であり、日本のSIer・エンタープライズの利用実態に直接関わる。
- 「解析器と実行系の解釈差はフェイルクローズで塞ぐ」という修正方針は、自前でAIツールの統制を作る際にも流用できる設計原則。

### 自分の業務への示唆

**Claude Code 組織展開の標準に「権限設定は破られ得る前提の多層防御」と「セキュリティ修正への追随手順」を明文化する材料になる。**

- 許可ルールだけに依存せず、サンドボックス・ネットワーク統制・監査ログを重ねる構成を標準に書く根拠として、この実例を引用できる。
- 組織展開では「どのバージョン以降を許可するか」「セキュリティ修正リリースを誰がどう周知・強制するか」という運用設計が必要になることを示している。
- Windows端末中心の組織では、PowerShell 5.1 経由の利用を統制の検証対象に含める必要がある。

### 推奨アクション

**自組織・自環境の Claude Code バージョンを確認し、AI開発標準ドラフトに「バージョン追随と多層防御」の節を追加する。**

- 自環境と周囲の利用者のバージョンが v2.1.214 以降かを確認し、旧い場合は更新する。
- AI開発標準ドラフトに「権限設定は多層防御の一層として扱う」「エージェントCLIのセキュリティ修正への追随手順(周知・期限・確認方法)」を1節書き足す。
- 工数: 30分。
