## DB-20260725-01 Claude Code v2.1.219:Claude Opus 5 がデフォルトOpusに、サンドボックスの厳格許可リスト設定を追加

**要点: モデルのデフォルト変更とネットワーク統制設定の追加が同時に来た。組織展開用の標準設定を更新すべきリリース。**

### 確認された事実

Claude Code v2.1.219 がリリースされた(2026-07-24付)。リリースノートによると以下が追加された。

- **Claude Opus 5(claude-opus-5)を追加し、デフォルトの Opus モデルに**。1M コンテキスト、fast モードは $10/$50 per Mtok。
- **`sandbox.network.strictAllowlist` 設定を追加**。サンドボックス化されたコマンドについて、許可リスト外のホストへの接続をプロンプトなしで拒否する。
- **`DirectoryAdded` フック**を追加。`/add-dir` または SDK の `register_repo_root` でセッション中に作業ディレクトリが登録された後に発火する。
- headless の stream-json init イベントに **`mcp_server_errors`** を追加。設定バリデーションでスキップされた `--mcp-config` エントリを列挙する。

### なぜ重要か

**「AI生成コードの実行統制」を設定ファイルで宣言的に固定できる範囲が広がった。**

- `strictAllowlist` はアウトバウンド通信のデフォルト拒否を「プロンプトなし」で強制でき、利用者の判断に依存しない統制になる。
- デフォルトモデルの変更は、組織内の全利用者のコスト・挙動に一斉に影響するため、展開側での周知・検証が必要になる。

### 自分の業務への示唆

**Claude Code 組織展開の標準 settings に、ネットワーク許可リストの厳格化を組み込む判断材料になる。**

- 開発標準の「実行環境の統制」節に、`sandbox.network.strictAllowlist` を統制手段として位置づけられる。
- `DirectoryAdded` フックは「どのリポジトリでAIを使ったか」の記録・ガバナンス自動化に使える可能性がある。

### 推奨アクション

**組織展開用の設定テンプレートで `sandbox.network.strictAllowlist` の挙動を検証する。**

- 自組織の標準 settings 案に許可リスト方式を追加し、実際の開発フローで支障が出ないか確認する。
- 工数: 30分。
- 完了条件: 標準設定ドラフトに当該項目と検証メモが追記されている。

## DB-20260725-03 InfoQ講演「自律的データプロダクト」:GenAI時代のデータアーキテクチャとMCPによる統制

**要点: 「データプロダクトをコンテナのように扱い、MCPの段階的ツール発見で統制する」という、AI前提のデータ基盤設計論。**

### 確認された事実

InfoQ が Jörg Schad 氏の講演を公開した。内容は summary によると以下の通り。

- 複雑化したデータ管理(data management hairball)を整理し、AI向けにスケーラブルで安全なアーキテクチャを構築する方法を解説。
- 「自律的データプロダクト」は、パイプライン・スキーマ・メタデータをカプセル化する、データにとってのコンテナのような存在として機能する。
- MCP 等のプロトコルによる段階的なツール発見(progressive tool discovery)が、コンテキストの劣化(context rot)を抑え、ガバナンスポリシーを強制し、信頼性のあるマルチモーダルアクセスを確保する。

### なぜ重要か

**AIの組織展開で必ず問われる「AIに社内データをどう安全に触らせるか」への、アーキテクチャレベルの回答例。**

- ガバナンスをデータプロダクト側にカプセル化し、MCP 経由のアクセスで強制するという構図は、個別アプリごとの統制よりスケールする。
- 「context rot をツール発見の設計で抑える」という論点は、エージェント設計と統制設計が同じ場所で交わることを示している。

### 自分の業務への示唆

**顧客のデータ基盤案件・自社AI標準の両方で「AI前提のデータアクセス統制」を語る語彙になる。**

- SIer として、既存データ基盤を「AIから使える形」に再設計する役務(データプロダクト化+MCP層整備)は継続収益型のメニューになりうる。

### 推奨アクション

- 「カプセル化するもの(パイプライン/スキーマ/メタデータ)」「強制するポリシー」「ツール発見の段階設計」の3観点で整理する。
